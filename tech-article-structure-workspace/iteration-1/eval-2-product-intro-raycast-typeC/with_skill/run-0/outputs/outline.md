# アウトライン — 週末に作った Raycast 拡張の紹介記事

## 記事タイプとストーリーパターンの判定

- **記事タイプ: C — プロダクト紹介**
  - 理由: 読者に渡したいものは「こんな拡張がある」という存在の認知と「インストールして使う」という再現手順。読み終えた読者が最初に取る行動が「インストールして試す」＝タイプ C の判定基準そのものだから。
- **ストーリーパターン: パターン1 — 違和感 → 転換点 → 新常識**
  - 理由: 「週末に作った」＝自分が日常で感じた小さな不満（違和感）が出発点になっており、それを解消する道具として拡張を見せると、ただの機能列挙より「なぜ要るか」が伝わりインストール動機が立つから。タイプ C は本来短く軽快に書くので、リードだけにこのパターンを効かせ、本文はデモ中心に保つ。

## タイトル案

1. 「Raycast でその一手間が消える — 週末に作った拡張を公開した」（違和感解消を主張に含める案）
2. 「あの操作、毎回ランチャーから2クリックしてた。Raycast 拡張にして1コマンドにした」（具体的ビフォーを見せる案）
3. 「週末ハックで Raycast 拡張を作って Store に出した（インストール手順つき）」（再現性を前面に出す案）

→ 推奨は案2。違和感（毎回2クリック）と転換（1コマンド化）が一読で伝わり、タイプ C の「使ってもらう」目的に最も寄与する。
