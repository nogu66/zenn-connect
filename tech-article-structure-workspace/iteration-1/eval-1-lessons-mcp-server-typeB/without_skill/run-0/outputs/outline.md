# 記事アウトライン

## タイトル案
- 本命: 「自作 MCP サーバーでハマった話 — ツール設計のやり直しと認証地獄から学んだ設計指針」
- 代替1: 「MCP サーバーを自作して学んだ、ツール設計と認証の落とし穴」
- 代替2: 「何度もツール設計をやり直した僕が、最初から知りたかった MCP サーバー実装のコツ」

## 読者ターゲット
- これから自作 MCP サーバーを書こうとしている人
- 一度書いてみたが、ツールが LLM にうまく使われず悩んでいる人
- MCP の認証まわり（OAuth / トークン）で詰まっている人
- =「過去にこの問題で詰まった自分自身」

## この記事のゴール（読者の便益）
- ツール設計のやり直しを減らせる「最初から押さえるべき設計原則」が分かる
- 認証で詰まるポイントとその回避策が分かる
- 試行錯誤の遠回りを、読者がショートカットできる

## 記事の骨組み（章立て）

### 1. はじめに
- 何を作ったか（1〜2行で背景）
- 想定読者と、この記事で扱う範囲 / 扱わない範囲
- 結論の先出し: 「ハマったのはツール設計と認証。原因は◯◯だった」

### 2. 前提: MCP サーバーとは何か（最小限）
- MCP の役割を1段落で（LLM と外部ツールをつなぐプロトコル）
- 自作する動機（既存サーバーで足りなかったこと）
- 詳細は公式ドキュメントへ誘導（深掘りしない）

### 3. ハマりどころ その1: ツール設計を何度もやり直した
- 症状: LLM がツールを呼ばない / 誤った引数で呼ぶ / 呼びすぎる
- なぜ起きたか（What/Why）
  - ツールの粒度が細かすぎた / 粗すぎた
  - 説明文（description）が LLM 視点になっていなかった
  - 引数スキーマが曖昧だった
- どう直したか（How）
  - 「1ツール=1ユースケース」に寄せた
  - description を「いつ使うべきか」起点で書き直した
  - 入力スキーマを enum / 必須項目で締めた
- Before / After のコード比較

### 4. ハマりどころ その2: 認証まわりで詰まった
- 症状: ローカルでは動くが接続時に弾かれる / トークンの渡し方が分からない
- なぜ起きたか（What/Why）
  - MCP のトランスポート（stdio / HTTP）で認証の前提が違う
  - シークレットの受け渡し場所（env / ヘッダ）を取り違えた
  - OAuth フローの責務分担を誤解していた
- どう直したか（How）
  - トランスポート別の認証パターンを整理
  - シークレットは環境変数経由に統一
  - 実際に動いた最小構成のコード

### 5. 学んだ設計指針（まとめの一般化）
- ツール設計のチェックリスト（5項目程度）
- 認証のチェックリスト（3項目程度）
- 「最初からこうしておけば良かった」リスト

### 6. おわりに
- 試行錯誤の総括
- 今後やりたいこと（テスト自動化、複数クライアント対応など）
- 参考リンク

## 図・コードの配置方針
- 3章: ツール定義の Before/After コード
- 4章: トランスポート別認証パターンの表 + 動作する最小コード
- 5章: チェックリスト（箇条書き）

- 一文一義、能動態
