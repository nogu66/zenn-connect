## タイプA — 実践ガイド（How-to / 使い方）

**渡したいもの:** 「いつ・どう使うか」の判断基準。手順そのものより「なぜその道を選ぶか」。

**典型アウトライン**

1. **リード（1〜3段落）** — 現状の不満 + 自分の転換点
2. **Why / 理由** — 見出しごとに価値を1つ
3. **始め方** — 過剰な仕組み化への警告（「まずはプロンプトから」）
4. **場面別の使い分け（Use Cases）** — カテゴリ別 + コピペ用プロンプト例 + 「こういうときに使う」
5. **FAQ** — 反論処理（コスト、時間、トレードオフ）
6. **締め** — 価値・感情（「in the loop でいられる」など）

**変形：判断フレーム型（例: Session Management 記事）**

- リードで「諸刃の剣」などテーゼを先に置く
- `## 最小限の前提（Primer）` で用語を先に定義
- **決断フレーム**を提示（例: 「毎ターンは分岐点」）
- 選択肢を**同じ粒度**で並列説明（続ける / 巻き戻す / クリア / 圧縮 / サブエージェント）
- `## まとめ` で決断フローを1枚に圧縮

**日本語で書くときに意識すること**

- 「やり方」より「いつ・なぜ別の道を選ぶか」
- 各セクションに**コピペ用プロンプト例**を置く

## タイプB — エンジニアリング教訓（Lessons）

**渡したいもの:** 「何を学んだか・なぜそう設計したか」。実装テクニックより制約下の設計思考。

**典型アウトライン（ルール列挙型）**

1. **フック** — 業界あるある・ミーム1行
2. **外部リソースへ委譲** — 基礎は別記事に逃がし、本記事は実戦の教訓に集中
3. **見出し = ルール1つ**（断言形・禁止形）
4. **各ルール内:** 直感 → 制約 → 代替設計 → 小さな事例
5. **`## 学んだこと（Lessons Learned）`** — 番号付きで再掲（スキャン用）

**変形：Attempt 連載型（例: Seeing like an Agent 記事）**

1. 抽象的な問題の提示
2. **比喩**で世界観を固定（1記事1つ）
3. ケーススタディの連鎖: 課題 → 試行1 → 失敗理由 → 試行2 → … → 最終解
4. 締め: 「Art, not a Science」— 厳格なルールはないと明示

**変形：カタログ型（例: How We Use Skills 記事）**

1. 問題（柔軟すぎて何を作ればいいかわからない）
2. 前提の訂正（よくある誤解の解消）
3. **Taxonomy**（カテゴリ列挙 + 各カテゴリに Examples）
4. 横断的な Tips
5. 配布・運用まで話を広げる
6. 謙虚な締め（「これは grab bag」「小さく始めた」）

**日本語で書くときに意識すること**

- 見出しを**断言形・禁止形**にするとスキャンしやすい
- **検討したが採用しなかった案**を書くと信頼感が増す

## タイプC — プロダクト紹介

**渡したいもの:** 「こんなものがある」という存在の認知と、再現できる手順。

**典型アウトライン**

1. **何ができるか**（1段落）
2. **始め方** — インストール or リンク
3. **事例** — 目的 + プロンプト全文 + スクショ/動画
4. **コツ**（1行）
5. **締め** — 共有・フィードバック依頼

**ポイント**

- 理論より**デモとプロンプトの再現性**
- 長文の Lessons / 実践ガイドとは別物として、短く軽快に
- 事例は「目的→プロンプト全文→結果の画像」をワンセットで積む
